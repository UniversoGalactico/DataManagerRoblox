# API and integration contracts

Config (unknown options rejected): StoreName (required without Store), optional Scope, Template (dictionary, default {}), SchemaVersion (positive integer, default 1), Migrate(data, oldVersion, newVersion) (optional deterministic non-yielding function returning a dictionary), SessionTimeout (30–3600 seconds, default 180), AutosaveInterval (>=5 and <= half timeout, default 60), Attempts (1–8, default 4), MaxConcurrentSaves (1–16, default 4), OnError(key, code) (optional diagnostic callback), Store (trusted UpdateAsync-compatible adapter).

Load uses a new GUID per acquisition and does not automatically wait for a foreign owner. Retry SESSION_LOCKED with a bounded delay. Never substitute a blank profile after a load failure. Key is a server-derived UTF-8 string of 1–50 bytes without control characters. One manager per logical store is recommended; distinct instances contend through the same stored record.

Set copies and validates the entire profile; Get/Snapshot return detached copies. Profile root is a string-key dictionary. Nested arrays must be contiguous; no mixed keys. Limits: 20,000 visited values, depth 32, aggregate string bytes 512 KiB, individual string/key 65,536 bytes, finite numbers of magnitude <=2^50. These limits are not a serialized byte guarantee. Empty tables have ambiguous array/dictionary representation in DataStore. No automatic merging with template for existing data; use migrations.

Save serializes per profile: SAVE_BUSY means retry later. A save captures an immutable snapshot; mutations during a save are retained locally for the next save. Release freezes writes immediately, including when SAVE_BUSY is returned; ambiguous release stays frozen. Retry the same handle, not a new load. Ownership mismatch discards the stale profile. A marker makes a retried release idempotent while no newer acquisition has replaced it. Lost acknowledgement after newer acquisition cannot prove success.

Close permanently stops new loads and writes, attempts bounded concurrent release, waits for in-flight loads, and reports SHUTDOWN_INCOMPLETE if the deadline expires. Close may be retried, but a server shutdown may terminate outstanding work. SHUTDOWN_SESSION_LOST means a profile lost ownership during close; it is not a confirmed release. Close does not certify earlier operations. The module cannot guarantee final persistence.

Migration: only between v3 envelope schema versions. Migrate receives a detached copy and may be invoked multiple times by UpdateAsync; no yields or external side effects. Higher or unknown schemas fail closed. Legacy raw records are rejected. Stop all old writers and back up/export data before designing an explicit migration to a fresh store. Roblox object serialization from previous versions is not supported.

Storage format: Format=3, Schema, Data, Lease={Token,At,Duration} while owned, WriteId, ReleasedToken after release. Do not edit envelopes directly. The module preserves existing DataStore key metadata and user IDs when provided by UpdateAsync; it does not assign new associations automatically. External writes must honor this exact protocol or not write to these keys.

Operational limitations: service errors can leave an orphan lease until expiry, saves can be throttled, locally active profiles can lose remote ownership before the next save; a conservative monotonic deadline freezes handles without a confirmed renewal, server wall-clock skew beyond grace can change takeover timing. Takeover uses the stored owner's timeout; renewal does not move its wall-clock timestamp backwards. Autosave concurrency is bounded; explicit Save/Load calls are caller-controlled. No cross-key transactions, crash-proof backups, or exactly-once external rewards.
